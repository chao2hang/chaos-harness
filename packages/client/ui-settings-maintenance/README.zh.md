# @deepseek-ai/dsh-client-ui-settings-maintenance

[English](README.md) | 中文

Web 设置中的**系统维护**分区：展示当前服务的运行状况，并提供替换其进程的控件。浏览器插件以 id `maintenance`、order 30 注册一条本地化的 `settings.section` 贡献，因此它排在设置导航的末尾；导航条目与面板外壳由设置外壳拥有。

分区自身不发起任何读取。它的状态卡片与重启可用性都来自连接持有的、以连接代际为界的 Host 描述——与其他浏览器界面读取的 `host.describe` 结果同源——因此它展示的版本、工作目录与活动会话数，正是下一个会话真正启动时所处的值。

## 重启

重启控件向 Host 请求 [`host.restart`](../../host/apiproxy/README.md)：用相同命令行启动的后继进程替换当前服务进程。这是让声明了 `applies: 'restart'` 的设置、插件的增删以及重新构建的模块代码生效的唯一途径。

这一界面由三条性质决定：

- **重启需要确认。** 控件会打开一个风险确认框，其中写明当前挂载的会话数量；在勾选知情确认之前，确认按钮不可用。每个挂载会话正在进行的回合都随前一个进程一同结束。
- **重启只能作为一次往返被观察到。** Host 先应答、再停止，因此该响应不能证明后继进程的任何状态。分区因此等待 Host 描述先消失、再返回，只有两半都发生后才报告成功。前一个进程仍在应答期间重新发布的描述不会结束等待；被拒绝的请求也不会因为随后一次无关的重连而变成成功。
- **不可用的能力被明确说明，而不是藏在一个注定失败的按钮后面。** 启动方式无法拉起后继进程的部署会报告 `canRestart: false`，分区随即说明原因而不提供该控件。尚未建立连接代际时同理：没有描述就没有可重启的对象。

把该插件从 `cordis.yml` 中组合掉会整体移除这个分区——导航行随其注册一同消失，`host.restart` 也就无人调用。

## Model Experience

无。该包仅在浏览器设置中渲染 Host 拥有的部署快照，不注册任何面向模型的内容。

#### KV Cache effect

无；该包既不组装也不发送 provider 请求。

## Known Limitations and Deferred Work

- **重启进度是组件本地状态。** 在重启期间关闭设置面板会丢弃分区的等待状态，此后只剩连接自身的重连提示。对于并非由它发起的重启（包括另一个浏览器标签页发起的），分区不显示任何进度。
- **等待没有截止时间。** 始终无法绑定端口的后继进程会让分区一直报告"仍在等待"：这个说法准确，但不会自行结束。要区分启动缓慢与启动失败，需要浏览器无法获取的 Host 侧证据。
- **状态是连接代际的快照，而非实时数据流。** 活动会话数在建立连接代际时刷新，因此在别处新建的会话要到下一次握手才会体现。
