# Agent Note: 移动端抽屉隔离会话表面

Status: implemented

[English](2026-08-17-mobile-drawer-composer-isolation.md) | 中文

## 问题

在手机端抽屉断点以下，侧边栏会作为覆盖层渲染，而会话栏仍挂载在其下方。会话 composer 可能占据视口底部；侧边栏打开时，其控件可能透过抽屉显示，或在抽屉旁边仍可命中。半透明遮罩不能提供抽屉前景表面的隔离。

## 决策

手机侧边栏抽屉打开时，`AppFrame` 在 frame 上设置 `data-drawer-open`。该状态下，frame 隐藏仍挂载的中心栏；抽屉保持可见并可交互，位于遮罩上方。遮罩和抽屉使用独立的高层叠放范围，高于固定定位的会话控件；抽屉通过侧边栏填充 token 保持不透明。会话栏继续挂载，因此打开和关闭抽屉不会丢失会话或草稿状态。

手机抽屉继续使用 280px CSS 宽度。设备像素比为 1.5 时，截图会显示为 420 个物理像素；物理宽度不是另一条 CSS 尺寸规则。这项 frame 级隔离与[移动端底部抽屉表面](../feature/2026-08-17-mobile-bottom-sheet-surfaces.md)中通过 portal 挂载的选择器和设置抽屉互为补充，不替代它们各自拥有的关闭行为。

## 考虑过的替代方案

**只提高遮罩的 z-index。** 否决，因为遮罩有意保持半透明，composer 仍会透过遮罩可见，且抽屉之外挂载的中心栏仍可能参与命中测试。

**抽屉打开时卸载会话栏。** 否决，因为卸载会破坏呈现连续性；视觉隔离不需要卸载。

**将抽屉扩大到截图的物理宽度。** 否决，因为表面上的 420px 是设备像素比 1.5 下的 280px CSS 抽屉；修改 CSS 宽度会让普通手机视口中的抽屉过宽。

## 后果

打开手机侧边栏时，会话栏的所有绘制和交互（包括 composer）都会暂时隐藏，同时保留其挂载状态。抽屉在 280px CSS 面板内拥有交互，遮罩在剩余视口内负责关闭。关闭抽屉后，会话栏恢复显示，其草稿、滚动位置和会话状态不变。AppFrame 行为测试断言打开标记，组装后的浏览器探针验证中心栏隐藏且抽屉设置仍可命中。
