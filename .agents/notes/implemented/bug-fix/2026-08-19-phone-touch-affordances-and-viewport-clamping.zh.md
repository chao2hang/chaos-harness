# Agent Note: 手机端触控可用性与视口裁剪

Status: implemented

[English](2026-08-19-phone-touch-affordances-and-viewport-clamping.md) | 中文

## 问题

在 320/390/414 CSS px 下对 Web GUI 做了一轮实机检查，发现了底部抽屉工作（[底部抽屉表面](../feature/2026-08-17-mobile-bottom-sheet-surfaces.md)）未覆盖的缺陷：它们不在弹层里，而在常规界面框架中。

缺陷分三类。**行内容溢出视口并因此丢失。** `ContextInjectionRow` 的来源标签在 `flex: none` 下声明了 `text-overflow: ellipsis`，无法收缩，向列外溢出 82px；消息时钟溢出 157px，因为 `@media (hover: hover)` 让触控设备始终显示完整的 `时钟 · 用时 · 首 token · 速率` 读数，而它所在的行既不换行也没有可收缩的子元素。会话统计弹层保留了桌面的 `right: 0` 锚定，因此挂在靠左触发器上的 270px 面板把自己的左半列裁到了屏幕外。**仅悬停可见的操作无法触达。** 工作区树只在 `:hover` 时显示重命名、派生和归档，而触控屏永不产生该状态；悬停预览卡在点按时打开，并绘制到抽屉右侧的屏幕之外。**手机抽屉表现得像桌面列**：打开会话后它仍覆盖着刚刚选中的对话，且其遮罩使用 `--dsw-alias-bg-mask-drop`——浅色主题下是 70% 的白色，覆在白色页面上完全不可见。

两处布局故障加剧了上述问题。Hero 状态复用了会话视图的手机规则，其可增长的 `.sessionBody` 变成一个占满剩余高度的空盒，把 hero 压在约 590px 空白之下。整套框架中为鼠标绘制的控件——28px 输入区药丸、34px 发送圆钮、32/34px 树行、28px 头部圆钮、27px 视图标签——均低于任何触控目标下限。

## 决策

**手机规则重新声明触控指针所需的几何，并且每个裁剪值都按其所依据的控件尺寸重新计算。**

尺寸以既有的手机抽屉断点（`max-width: 640px`，`columns.ts SIDEBAR_DRAWER_BREAKPOINT`）为准，使抽屉、树与输入区由同一宽度决定；设置抽屉保留自己的 600px 断点。输入区圆钮变为 40px、发送 44px，树与头部控件 40px，树行 44px，视图标签通过内边距增高，使 `.tab::after` 仍把下划线钉在底边。行间距降至 8px 且 `.tools` 不再收缩，于是模型标签——唯一带省略号的控件——承担空间缺口，而不是模式药丸被压成零宽；低于 360px 时尾部控件组独占一行，避免模型药丸退化成一个孤零零的箭头。

依赖悬停的显示规则迁移到 `@media (hover: none)`，它陈述的是真实条件：树常驻显示行操作并让出相对时间，复现桌面悬停时的组合；`HoverCard` 则完全不显示。`HoverCard` 同时在首选一侧放不下时翻转到锚点左侧并夹入视口，因此窄桌面窗口也无法把它推出屏幕。

`ILayout` 新增 `dismissDrawer()`，由导航类动作调用——外壳的新建会话，浏览区的打开、启动与派生会话。布局 store 新增 `drawer`，作为 AppFrame 手机判定的纯镜像，使该动作能区分"覆盖式抽屉"与"共享列"；跨越该断点仍保留 `narrowExpanded`，只有 `setNarrow` 会清除它。两个抽屉遮罩改用 `--dsw-alias-bg-mask-1` 与 `--dsw-mask-blur`，即其他所有全视口可关闭层已在使用的压暗方式。

统计弹层在手机宽度下成为钉在视口上的抽屉，与模型、权限和上下文计量选择器一致，并取用共享 Modal 的 z-index 层级，使输入区的选择器根节点——在该宽度下即便关闭也持有 `1000`——无法透穿其上。当输入区座位承载 hero 时，`.sessionBody` 不再增长，从而恢复 `.scrollBody` 自身的居中。外观选项共享一行而非堆叠，设置关闭按钮离开文档流移至面板角落，使手机抽屉的标题只占一行而非三行。

## 备选方案

**用 `matchMedia('(hover: hover)')` 在 JavaScript 中抑制悬停卡。** 否决：jsdom 对任何查询都返回 `matches: false`，组件自身的规格会因此不再渲染它所断言的卡片。呈现规则属于 CSS，既有的 `MessageIconActions` 悬停开关已在那里。

**只截断消息时钟而不让其所在行换行。** 单独采用被否决：截断是可靠的下限，但换行保留了完整的运行读数，而这是触控用户唯一能看到它的地方。该行两者兼用——先换行，省略号兜底——因此任何宽度都不会溢出。

**手机端保持 hero 贴底。** 否决：居中位置下输入区已在拇指可及范围内，而贴底形态让列的上三分之二完全空白，读起来像渲染失败而不是布局。

**通过根字号或令牌统一缩放所有控件。** 否决：这些尺寸是逐组件的 figma 几何，并带有硬编码的配套值（`.headerActions` 按 28px 控件对的精确宽度限制折叠后的控件簇），全局缩放会移动已绘制的框架却修不好这些计算出来的裁剪值。

## 影响

手机端框架变高：输入区行、树行和抽屉头部各增加约 12px，而设置面板的头部由三行减为一行，收益远超代价。`(hover: none)` 下的树常驻显示省略号按钮并隐藏相对时间，触控用户以时间戳换取可触达的行操作。`HoverCard` 在触控端不渲染，因此其内容绝不能是某个事实的唯一出处——行标题与复制操作仍独立可用。

`ILayout` 增加一个方法；所有实现与测试替身都需提供它，`ui-workspace` 也因此新增了此前未声明的 `layout` 服务依赖边。抽屉现在会在导航时关闭，想连开多个会话的手机用户需要每次重新打开它。

两处裁剪值仍是手工计算的——折叠后的搜索槽位与头部操作簇——日后变更控件尺寸必须重新计算；它们在 `browser-styles.client.spec.ts` 中按手机断点被断言，因此漂移会在那里失败，而不是在截图里。

## 验证

`pnpm run test:gui`（274 个文件）通过。`browser-styles.client.spec.ts` 增加了可识别 at-rule 的选择器读取——条件覆盖不再并入它所覆盖的基础规则——以及对触控行高、头部控件尺寸和 `(hover: none)` 显示规则的断言。`ui-workspace` 与 `ui-sidebar` 的 `apply.client.spec.ts` 断言每个导航动作都会关闭抽屉。检查本身是在克隆会话数据的 `dsh web` 实例上，用真实 chromium 于 320/390/414 逐个界面执行的，检查是否有元素越过视口边缘、是否存在小于 36px 的可交互盒；除轨迹表内部的 span（其父元素已做省略号处理）外，两项报告均为空。
